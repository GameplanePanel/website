## Build the evidence bundle

Start with desired spec and observed status, then correlate events, workload state, component logs, audit records, and recent changes.

<DocsSectionList
  items={[
    { icon: "check", label: "Record timestamps", text: "Record exact timestamps and timezone for every exported source." },
    { icon: "check", label: "Separate logs", text: "Separate Gameplane API/operator logs from game-container failures." },
    { icon: "check", label: "Preserve first error", text: "Preserve the first error; later retries often hide the original cause." },
  ]}
/>

## Common failure families

Classify the symptom before choosing a runbook: Pending, image pull, crash loop, probe, volume, service, auth, backup, or source sync.

<DocsSectionList
  items={[
    { icon: "check", label: "Pending", text: "Usually points to capacity, placement, PVC, or scheduling policy." },
    { icon: "check", label: "No console output", text: "Can mean the container never started or the game stream isn't ready." },
    { icon: "check", label: "Restore and module failures", text: "Require destination/source credentials and controller logs." },
  ]}
/>

## Escalate with context

When local checks are exhausted, share a minimal reproducible case without secrets, tokens, world data, or player information.
