  <ChangeEntry version="Unreleased" date="next release" highlight>
    These changes ship in the release after v0.4.3.
    **SSO group role rules:** an SSO provider maps IdP groups to any role, including custom roles, with an ordered rule list where the first match wins. Roles set by hand on the Users page are kept at sign-in.
    **Personal MCP tokens:** users create read-only MCP tokens in the API, valid for 7, 30, 90 or 365 days and revocable at any time. The API adds read routes for pods, Kubernetes events and pod logs.
    **MCP tokens page:** Settings → MCP tokens creates, copies and revokes personal MCP tokens, shown once with a ready-to-paste client configuration.
    **MCP events warning:** when `list_events` returns more than 100 events across clusters, the unavailable-cluster warning still appears after the truncation notice.
    **Upgrade: MCP server namespace scope:** the break-glass MCP server no longer reads every namespace. It reads only the release and managed game namespaces, so use personal MCP tokens for per-user reads across clusters after upgrading.
    **CurseForge and FTB modpacks:** the Modpacks tab installs, pins and removes Modrinth, CurseForge and FTB modpacks at a chosen version, so a restart never upgrades a pack by surprise.
    **Share link wake access:** owners can turn wake access on or off for an existing share link in Settings → Share links, and the change applies to everyone with the URL.
    **Backup schedules from a server:** the Backups tab edits or deletes a schedule, and **Managed by server settings** opens the settings that control the automatic schedule.
    **Template hostnames:** `operator.templateHostnames` sets a default hostname for NodePort and LoadBalancer servers using a template. A hostname set on a server takes precedence.
    **Backup destinations from settings:** destination managers open the selected server's cluster and namespace from Settings → Scheduled backups, and Back up now links there when the server has no destinations.
    **Module updates:** minecraft-java 2.13.0 adds CurseForge and FTB modpack installs (needs Gameplane 0.5.0), a new Minecraft Proxy module is added, and Valheim shows a player count read from the Steam query. Installed modules keep their version until you upgrade them.
    **SFTP access:** set `sftp.enabled=true` to browse, upload and download server files with FileZilla, WinSCP or `sftp`, under the Files tab permissions and audit log. Uploads are capped by `files.maxUploadSize` (default `20Gi`).
    **SFTP with SSO accounts:** SSO accounts, named by their email address, can log in with their panel username. An unregistered SSH key falls back to the password prompt.
    **Server name rule:** a server name that starts with a digit or is longer than 57 characters is refused at create or clone time with a clear message. An existing server with such a name shows Failed with the reason.
    **Upgrade: chart CRD hooks:** the chart no longer bundles the `gameplane-crds` subchart, and hooks install the CRDs and ModuleSources instead. Air-gapped clusters must mirror `crds.autoApply.image`, and `helm uninstall` no longer removes the default and upload ModuleSources.
    **Per-server security overrides:** modules set the run-as user and group, filesystem group and volume ownership check, and owners with `servers:security` can override them. Overrides apply on the next restart, and root overrides are off by default.
  </ChangeEntry>

    **Publishes 0.4.2:** the 0.4.2 release stopped at a HIGH image scan finding, so 0.4.3 ships every 0.4.2 change plus a libxml2 update in the dashboard image (CVE-2026-86144).

  <ChangeEntry version="v0.4.2" date="2026-11-20">
    **Port pools:** `operator.portPools` lets servers share one public address, with each server keeping its own block of ports.
    **Load-balancer class:** a LoadBalancer server can set `spec.networking.loadBalancerClass` to choose which implementation handles its Service.
    **Hostname endpoints:** a LoadBalancer server with a hostname shows that hostname as its address once the load balancer has published one.
    **Player counts over Steam A2S:** a module can read its player count from the Valve query with `capabilities.players.query`.
    **Separate CRD chart:** `gameplane-crds` is published as its own OCI chart at the same version as `gameplane`.
    **Minecraft operators in Players:** the Players tab lists configured Minecraft Java operators, including offline ones.
    **OpenEBS capacity:** cluster inventory can read an administrator-selected OpenEBS LVM thin pool instead of the node's system disk.
    **Components in their own repos:** the MCP server, audit-syslog bridge, tunnel clients and capture sidecar moved to their own repositories and are checked out as submodules.
    **Upgrade: hostname addresses:** LoadBalancer servers with `spec.networking.hostname` set now report that hostname as their address. Check that each hostname resolves to its server first.
    **Upgrade: git module source:** the default git module ref moves to the v0.4.1 module tag, which changes several module versions. Repin installed modules on git-source installs before upgrading.
  </ChangeEntry>

  <ChangeEntry version="v0.4.1" date="2026-11-17">
    **Server file manager:** expand folders, edit files with autosave, and download, archive or delete a selection.
    **Earlier log history:** the Logs tab pages back through earlier game-file output and container logs while the live stream stays connected.
    **Staged settings:** template fields with `applyOnRestart` save without replacing the running Pod, and take effect on the next start.
    **PostgreSQL high availability:** two or more API replicas on separate nodes can share one writable PostgreSQL primary.
    **Worker placement and limits:** reserve game workers with a node label and taint, bound CPU and memory per server, and set per-namespace quotas.
    **Tenant network isolation:** the opt-in `networkPolicies.tenantIsolation` profile restricts traffic between game workloads in managed namespaces.
    **Upgrade: credential boundary:** the chart requires Kubernetes 1.30+ with ValidatingAdmissionPolicy and PodSecurity admission. Migrate existing credentials before upgrading.
    **Upgrade: pod-local probes:** remove the explicit host from HTTP and TCP probes on GameServers and GameTemplates.
    **Upgrade: ARK module 2.x:** the module moves to the community image `hermsi/ark-server`, with the data volume at `/app`. Schedule downtime and move existing worlds before adopting 2.x.
    **Upgrade: amd64 workers:** ARK: Survival Evolved, Bannerlord, Nuclear Option, Squad and The Isle need amd64 workers. Set the `kubernetes.io/arch: amd64` selector on older GameServers.
  </ChangeEntry>

  <ChangeEntry version="v0.4.0" date="2026-11-10">
    **Independent central panel:** Docker Compose or a standalone Helm profile runs the API and dashboard without a local game cluster, while games run on registered clusters, each with its own operator and agents.
    **Languages:** the dashboard can be shown in other languages, set per account or as the instance default. French is the first pack, and a language is listed once it is at least 80% translated.
    **Extended telemetry tier:** a second, separately consented tier with a random install ID and fixed-set categories, signed reports, and a receiver dashboard with an optional public summary.
    **Credential maintenance:** standalone key custody, the offline `rotate-panel-key` command, and kubeconfig and gateway credential update endpoints.
    **Fleet-wide node inventory:** a Nodes page lists the nodes of every cluster you can see.
    **Optional Steam display names:** player lists can show Steam display names through a Steam Web API key.
    **Hell Let Loose withdrawn:** the module is removed from the official catalog, leaving 29 modules.
    **Security hardening:** a pre-release audit pass covering dial-guarded OIDC and registry requests, share-link traffic on its own Ingress, and a Content-Security-Policy in the dashboard.
    **Upgrade: admin-level grants:** `users:manage`, `roles:manage`, `config:manage` and `cluster:manage` no longer grant admin-level permissions unless the holder also has `*`.
    **Upgrade: kubelet probes:** a new per-server NetworkPolicy admits kubelet traffic only to probe ports; set `networkPolicies.probeIngress.enabled` to `false` for the old rule.
    **Upgrade: remote catalogs:** module and template catalog access on a remote cluster needs a cluster-wide grant there.
    **Upgrade: telemetry:** on by default for new installs after a first-login notice, an empty `api.telemetry.endpoint` now means the project receiver, and receiver `DASHBOARD_TOKEN` values must be at least 32 characters.
    **Upgrade: API singleton:** `api.replicas` other than 1 is rejected in every database mode.
  </ChangeEntry>

  <ChangeEntry version="v0.3.0" date="2026-10-05">
    **Multicluster gateways and unified server management:** an optional private mTLS agent gateway lets one dashboard and API manage authorized game servers across independent clusters, with optional location filters and routed console, files, players, mods and captures.
    **User theme customization:** Settings → Theme & Appearance offers preset themes (Modern Pink, Legacy Orange) and custom color selection with live WCAG AA contrast validation.
    **Network capture:** admin-only, on-demand packet capture from running game pods as ephemeral sidecars, exported as PCAPNG (Wireshark-compatible).
    **Module authoring toolkit:** gp-module CLI and web dashboard for scaffolding, validating, previewing, and packaging custom game modules.
    **PostgreSQL end-to-end support:** the PostgreSQL driver works end to end, with its own migration set, placeholder rebinding, and database tests in CI. It was experimental: keep a single API replica.
    **Install-time configuration:** Helm-seeded OIDC role mappings and default StorageClass for game-data PVCs.
    **Share link expiry options:** no-expiry, 15/30/60/90-day presets, or custom date picker.
    **Security audit remediation:** share link isolation, permission checks on GameServer mutations, Secret/ConfigMap reference validation, and symlink/zip-slip guards hardened across mod extraction.
    **Servers page multi-namespace support:** the Servers list shows servers from every namespace the viewer may read, not only the default games namespace.
    **Playit tunnel improvements:** NetworkPolicy egress widened to reach relay, and playit-assigned addresses show in status.
    **REST and CLI console protocols** for games with HTTP admin APIs (FiveM) and PTY-only games (Terraria).
    **14 new game modules** added in v0.3.0 (FiveM, Farming Simulator 25, Euro Truck Simulator 2, Mount & Blade Bannerlord, tModLoader, Team Fortress 2, BeamMP, Left 4 Dead 2, The Isle, ARK: Survival Evolved, Arma Reforger, Hell Let Loose, Squad and Nuclear Option), for 30 at the time of v0.3.0 with the 16 from v0.2.0-beta.8. Hell Let Loose was withdrawn in v0.4.0, leaving 29.
  </ChangeEntry>

  <ChangeEntry version="v0.2.0-beta.8" date="2026-08-22">
    Dependency sweep: Go module updates across telemetry-receiver, sentinel, mcp-server, operator, api and agent; web dependency bumps (`@tanstack/react-virtual`, `lucide-react`, `@types/node`, `globals`, `jsdom`, `postcss`); and CI/image pins aligned to stable releases (`setup-envtest` release-0.19→release-0.24, envtest Kubernetes 1.31.0→1.36.2, `kind` v0.24.0→v0.32.0, nginx 1.30→1.31, restic 0.18→0.19).
