Gameplane contributions flow through a design-first cycle for UI changes, a code-only path for backend work, and synchronized submodule updates. This guide covers the complete workflow from planning through PR review.

<DocsCallout icon="git-pull-request" title="UI work begins in design.pen before code.">
  Dashboard changes start in `design.pen` (Pencil) with maintainer review, then translate to React. Module and public-site work originates in their own repositories before a submodule bump.
</DocsCallout>

## Submit and review

Compile and commit focused changes with sign-off; CI verifies the full test, lint, and integration suite.

<DocsCallout icon="check" title="Every PR requires signed commits.">
  Use `git commit -s` to add the Developer Certificate of Origin footer. Include risk, affected test tiers, new tests, docs, and Pencil node IDs in the PR description.
</DocsCallout>

<DocsQuickReference
  label="CI VERIFICATION GATE"
  items={[
    "01  Compilation checks (go build ./..., npx tsc --noEmit) — run locally",
    "02  make generate && make manifests — if CRD/schema changes",
    "03  Full test, lint, e2e suite runs in CI after push",
    "04  Pencil exports synced; submodule changes committed separately",
  ]}
/>

Push your branch and create a PR. CI automatically runs the full verification suite (linting, unit tests, integration tests, E2E buckets). Reference the design screens, affected component contracts, and test evidence in the PR body to help reviewers. Once approved and all CI checks pass, the PR merges into `master`.
