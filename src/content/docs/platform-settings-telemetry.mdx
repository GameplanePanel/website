## Telemetry and privacy

Usage telemetry is on by default for new installs and is not a substitute for operational metrics and logs. Reports go to the project's provider at `telemetry.gameplane.net` unless the operator chose another destination or disabled telemetry. The project's [data-handling statement](../../telemetry/) lists exactly what is collected and how long it is kept.

On a new install the first admin to sign in sees a notice naming the destination and both tiers; nothing is sent until an admin has seen it. Admin Settings > Telemetry then shows the destination, a preview of the next report, the last attempt, separate switches for the basic and extended tiers, and an install-ID reset. Turning basic off turns extended off with it.

**Basic** sends only the Gameplane version, the GameServer count and the GameTemplate count. **Extended** adds a random install ID, the Kubernetes minor version, a distribution category, CPU architectures and a node-count band, server counts per official module (custom modules are one combined count), feature adoption flags and bands, the database kind, the UI language, a public signing key and the send time. Every value comes from a fixed set or is a number; names, namespaces, hostnames, addresses and player data are never sent.

## Updates and About

Update channel comes from Helm; record version, Kubernetes version, and license before troubleshooting or upgrading.

The Dashboard's Settings → About card displays the current Gameplane version (from the container image tag, set via Helm `image.tag`), the Kubernetes cluster version, and a fixed license identifier (AGPL-3.0). This information is useful for support diagnostics and version-specific feature eligibility.

- **Version**: The image tag set at install time or on upgrade. Leave empty in Helm values to use the chart's `appVersion`.
- **Kubernetes version**: Your cluster's API server version, visible in Dashboard Settings → About and via `kubectl version`.

Before opening a support ticket or upgrading:

1. Record your Helm chart version, `image.tag`, and any custom `values.yaml` overrides
2. Confirm the Kubernetes version your cluster is running
3. Note the exact Gameplane version and license shown in Dashboard Settings → About
4. If filing an issue, include these details to help narrow down version-specific bugs
